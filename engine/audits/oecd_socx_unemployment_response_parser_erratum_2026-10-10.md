# OECD spending-response parser erratum before first estimate

The first attempt to run the locked OECD/WDI family failed before constructing a country-year panel. The frozen runner read the selected SOCX columns into memory and then failed in `gdp_cells`: it selected five WDI columns, including `indicator_id`, but tried to unpack each row into four variables. The exception was `ValueError: too many values to unpack (expected 4)`. No sample count, transformed spending value, coefficient, sign, p-value, verdict, or result artifact was produced or inspected. The failed attempt did technically load selected SOCX values into memory, so this erratum does not claim that all source bytes remained unopened after the source lock.

The repair wrapper changes **only** WDI row unpacking to use `zip(country_iso3, year, value, obs_status)` after the same national-country filter, indicator check, and duplicate-key check. It leaves the preregistered SOCX selectors, country-year roster, spending transformation, GDP range, sample floors, fixed effects, covariance, concentration checks, fold assignments, and verdict gates unchanged. The original registration runner and source lock remain byte-identical and in separate earlier commits. The wrapper and this erratum are committed before the first successful run; the wrapper checks that ordering and checks that its own commit contains no result packet. Exact replay uses the wrapper.

The result is still a prospective post-lock measurement with a disclosed pre-estimate parser repair. It receives descriptive calibration visibility only and zero policy, causal, school, position, and featured credit. If a future review considers any post-access code repair disqualifying for prospective status, keep the visible measured result as a post-registration diagnostic and do not silently replace it with a different result.
